# 모바일 가로 UI 3종 비교

성인 공무원 수험생용 《합격하시든가, 쓰레기로 남으시든가》의 비교 시안입니다. A·B·C 각각 타이틀과 문제풀이 화면을 제공하며, 같은 검수 문항으로 배치와 조작 방식을 비교합니다. 기존 시연 캐릭터, 서고 배경, 남색·아이보리·버건디를 사용합니다.

## 실행

- 파일 실행: 이 폴더의 [index.html](index.html)을 더블클릭합니다. `assets`를 포함한 폴더 구조를 유지해야 합니다.
- HTTP 실행: `C:\ai_webtoon\siyeon-exam`에서 `npm run dev`를 실행한 뒤 [비교 페이지](http://127.0.0.1:4176/previews/mobile-ui/)를 엽니다.
- 각 카드의 **단독 열기**로 플레이어를 원래 크기로 확인합니다. 비교 페이지 안의 화면은 선택한 크기를 카드 폭에 맞춰 축소한 미리보기입니다.

플레이어는 가로 화면에서 사용합니다. 세로 화면에서는 회전 안내를 표시하고 문제 조작을 막습니다.

## 비교 방법

1. 상단에서 타이틀/문제풀이, 예제 문항, 화면 크기를 선택합니다. 세 시안에 같은 설정을 적용합니다.
2. 타이틀에서 시작하고, 지문을 읽은 뒤 **답안 보기**를 누릅니다.
3. 답을 선택하면 즉시 채점되고 해설로 이동합니다. 선택한 답은 잠기며 **답안** 탭에서 정답과 내 답을 확인할 수 있습니다.
4. **다음 문제**로 이동합니다. 마지막 문항에서는 **다시 체험**으로 처음부터 시작합니다.
5. **전체 초기화**는 세 시안을 첫 문항의 타이틀로 되돌립니다. 각 시안의 개별 조작 상태는 따로 유지됩니다.

**지문·답안·해설·자료** 탭과 이전/다음 쪽 버튼을 사용합니다. 긴 내용은 글자를 줄이지 않고 쪽으로 나눕니다. 원문 이미지는 **자료 확대**에서 전체 보기와 확대 구역을 넘겨 볼 수 있습니다. 일시정지 후 계속 풀기, `PageUp`/`PageDown`, 대화상자에서 `Escape`도 지원합니다.

## 세 시안의 차이

아래 장단점은 배치에 따른 비교 관점이며, 실제 사용자 사용성 시험 결과는 아닙니다.

| 시안 | 배치 | 장점 | 비교할 점 |
| --- | --- | --- | --- |
| A 서고 균형형 | 문제 70 : 시연 30, 하단 쪽 이동·주요 행동 | 시연의 표정과 문제를 함께 볼 수 있음 | 긴 지문은 B보다 더 많은 쪽으로 나뉠 수 있음 |
| B 시험지 집중형 | 넓은 시험지, 상단의 작은 시연 초상·반응 | 읽기 영역을 크게 확보함 | 캐릭터의 존재감이 작고 조작이 하단에 모임 |
| C 양손 게임형 | 왼쪽 쪽 이동, 중앙 문제, 오른쪽 시연·주요 행동 | 양쪽 엄지의 역할이 분명함 | 좌우 조작 영역이 폭을 차지하므로 작은 화면의 중앙 폭을 비교할 필요가 있음 |

비교 크기는 667 × 375, 844 × 390, 915 × 364, 1024 × 768입니다. 비교 페이지 폭이 1050px 이하이면 A·B·C 탭으로 한 시안씩 봅니다.

## 단독 플레이어 주소

`player.html?variant=a&screen=play&question=2024-0-1`

| 매개변수 | 값 | 기본값 |
| --- | --- | --- |
| `variant` | `a`, `b`, `c` | `a` |
| `screen` | `entry`, `play` | `entry` |
| `question` | 아래 문항 ID | 첫 문항 |

| 문항 ID | 동일하게 제공하는 예제 |
| --- | --- |
| `2024-0-1` | 국어 1번 · 일반 선택형 |
| `2024-0-17` | 국어 17번 · 긴 지문 |
| `2024-1-6` | 영어 6번 · 밑줄 어법 |
| `2024-0-12` | 국어 12번 · 그림 자료 |

## 데이터와 범위

[fixtures.js](fixtures.js)는 기존 문제 은행의 검수된 네 문항만 복사한 비교용 데이터입니다. 답변과 읽던 위치는 메모리에만 보관합니다. 새로 열거나 새로고침하면 초기화되며, 실제 학습 기록·진도·호감도·진행 중 실행·오프라인 캐시에 포함하지 않습니다. 음성은 없습니다. 시안 코드는 외부 요청, JSON fetch, ES 모듈, 브라우저 저장소를 사용하지 않습니다. HTTP 개발 서버가 삽입하는 개발 도구는 별도입니다.

자산 원본·용량·해시는 [ASSETS.json](ASSETS.json), 흐름과 크기 규칙은 [DESIGN.md](DESIGN.md), 검사 결과와 한계는 [REPORT.md](REPORT.md)에 기록했습니다.

## 검사 재현

프로젝트 의존성과 Microsoft Edge가 설치된 환경에서 `C:\ai_webtoon\siyeon-exam`을 작업 디렉터리로 사용합니다.

```powershell
node scripts/build-mobile-ui-fixtures.mjs
node scripts/mobile-ui-compare-audit.mjs
```

HTTP 검사는 개발 서버와 생성된 `dist/sw.js`가 필요합니다. `dist`가 없으면 먼저 `npm run build`를 실행합니다. 별도 터미널에서 `npm run dev`를 실행한 상태로 아래 명령을 실행합니다.

```powershell
node scripts/mobile-ui-http-audit.mjs
```

픽스처 명령은 비교용 데이터와 자산 명세를, 검사 명령은 `reports`의 JSON·캡처를 다시 생성합니다. 자동화 결과는 데스크톱 Edge 기준이며 실제 모바일 기기 검증은 포함하지 않습니다.
